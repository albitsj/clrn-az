# 真实录屏回归输入

这些附件只供断言回归测试使用，**不是正式截图基准，也不代表新的视觉批准**。
全部来自[运行 40903896735](https://github.com/albitsj/clrn-az/actions/runs/40903896735)
第一次运行的报告，覆盖 62 种转场、79 次采集，包括失败作业的全部重试以及其他作业已采到的转场。

`recordings.tar.gz` 保存 164 个去重后的原始附件：79 段 MP4 及对应原生首尾 PNG。
文件以原始字节的 SHA-256 命名，没有重编码、补帧、合成截图或修改视频。
`recordings.json` 记录原产物名称和附件路径、采集区域、既有遮罩、报告时间线、
原调用方已有的参考列表、原始视频帧的呈现时间及编码尺寸，并锁定归档摘要。
归档中的视频和截图在读取时再次逐项校验摘要。

应用提交为 `69f9251d3b5f2b93aa2d880d27abbeefe16ee645`，
发布版本为 `android-staging-300001001-69f9251d3b5f`，
安装包摘要为 `27618d750fc306b1a75d52d642b2d90f361501fd1b9998bc3cd65ca5874196f5`。
四个失败作业的日志、报告构建信息均与此一致。
被测仓库源提交为 `18fdf79e04f7c43a938e273abcf5e9e2cb453560`，
自动测试实际检出合并提交 `969d3279a2e43e6565d679a18b7df079bd4fda9f`，目标为 `47e1ba3`。

`recorded-transitions.test.mjs` 解开归档后，按生产路径的
`fps=30,scale=720:1280:flags=lanczos,crop=...` 解码整段视频，核对完整帧数，
应用报告中原有遮罩，再调用公开的选帧和空间断言。
30 帧重采样不代表设备实际输出 30 帧；报告中的 `timeline` 是生产路径生成的重采样时间线，
`nativeFrames` 则保留原始 MP4 的帧呈现时间和流信息。解码器在 Linux 使用锁定依赖中的可执行文件，
其他平台使用本机 `ffmpeg`；缺少解码器直接失败，不跳过用例。

接受距离只使用 `android/snapshots/` 中原先已经审查的中途相位；
首尾和本归档中的实际图仅用于输入与位置诊断，不增加可接受的参考。
回归测试只验证真实采集输入与通用中途断言的兼容性，不代替业务流程、首尾正式截图比较或新提交的设备运行。
比牌高亮框的独立分区失败也不在本转场测试中冒充通过，详见[调查记录](../../../docs/issue-31-current-failures.md)。
